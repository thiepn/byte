# Byte Main App — Overview & Activity — Phase 16

Phase 16 promotes the full application from a mostly skeletal shell into Byte's deeper investigation surface while preserving the original five-destination navigation.

The phase intentionally owns **Overview and Activity**. Apps & Diagnostics remains Phase 17, Customization Studio expansion remains Phase 18, and onboarding/settings system integration remains Phase 20.

## Overview

Overview is the deeper counterpart to the Quick Panel.

It presents:

- CALM / BUSY / STRESSED / NEEDS_ATTENTION
- current primary issue and plain-language explanation
- the diagnostic engine's existing safe recommended action
- CPU
- memory
- storage
- battery
- aggregate network throughput
- best-effort temperature
- small recent trend lines

The page refreshes from Byte's cached state every two seconds. It never performs a hardware sample itself.

### Trend policy

Trend points are generated by the existing telemetry worker after the normal snapshot has already been sampled and diagnosed.

A point contains:

- CPU percent
- memory percent
- storage percent
- optional battery percent
- aggregate download + upload Mbps
- optional temperature

Trend sampling is limited to at most one point every 15 seconds and a maximum of 240 points.

Trends are **session-only**. They are not written to disk.

This keeps Overview useful for answering "is this getting worse?" without creating a permanent raw telemetry archive.

## Activity

Activity is not a telemetry table.

It records only meaningful state changes:

- diagnostic issue opened
- diagnostic issue resolved
- charging started
- external power disconnected / running on battery

Normal CPU, memory, network, storage, temperature, or battery samples do not create timeline entries.

The timeline supports All, Issues, Resolved, and Power filters and groups events by local calendar day.

## Persistence

Meaningful activity events are stored in:

`activity.json`

The store:

- is local only
- uses atomic same-directory replacement
- keeps at most 200 events
- assigns monotonically increasing local IDs
- reloads events across application restarts
- does not persist trend points

If `activity_history_enabled` is false, Byte does not add new events or trends.

## Apps boundary

Phase 16 removes the skeletal Apps screen without implementing Phase 17 early.

The surface only displays a process when the existing diagnostic engine has already supplied a medium/high-confidence culprit. Otherwise it explicitly says that no single app stands out.

There is no continuous process leaderboard.

## Settings boundary

Phase 16 also removes the generic "reserved surface" experience from Settings, but keeps it read-only. It summarizes currently stored preferences and links back to Customize.

Launch integration, fullscreen lifecycle behavior, editable application settings, and onboarding remain outside this phase.

## Privacy and performance

Phase 16 does not add:

- additional hardware polling
- permanent raw telemetry storage
- keystroke content
- mouse coordinates
- continuous process ranking
- network analytics
- cloud history

The activity recorder consumes snapshots already produced by the single Rust telemetry pipeline.

## Acceptance

Phase 16 is complete when:

- Overview answers "How is my PC doing now, and is it trending?"
- Activity answers "What meaningful thing happened, and when?"
- normal telemetry does not flood history
- events survive restart
- numeric trends stay bounded and session-only
- the full app remains understandable rather than becoming Task Manager
